# 微知 · 测试与反馈手册

> 用途：你正式用起来之后，遇到 bug 怎么报、我怎么修、你怎么更新。

---

## 一、你正式用的时候，怎么反馈 bug

就在这个对话里直接说，**一句话 + 4 要素**：

1. 哪张卡 / 哪个日期 / 哪个页面
2. 你做了什么操作
3. 出现了什么现象（**截图最好**）
4. 当时是 WiFi 还是蜂窝网

**示例**：
> 「2026-08-13 的番茄工作法那张，点提交评分后一直转圈没结果，蜂窝网下」

---

## 二、我怎么复现 / 定位

- 查服务器日志：`journalctl -u weizhi-reader`
- 查数据库：`sqlite3 /opt/weizhi/app/weizhi.db`
- 必要时本地重跑该卡片的生成逻辑

不靠猜，先复现再修。

---

## 三、我怎么修 + 你怎么更新（关键：大多不用重装 APK）

架构：**APK 是 WebView 壳，里面加载的是服务器上的网页**。所以：

| 改动类型 | 我怎么做 | 你怎么做 |
|---|---|---|
| 后端 bug（评分 / 存储 / 状态机） | 改完重启服务，几秒生效 | **无感**，刷新即可 |
| 前端 bug（界面 / 交互 / 排版） | 改完 `reader.html` | **刷新一下**就变 |
| 壳级改动（图标 / 闪屏 / 离线策略） | 重打 APK | 覆盖安装一次 |

> 结论：**99% 的 bug，你反馈 → 我修 → 你刷新**，全程不用重装 APK。

---

## 四、验收标准（每次改完对照）

**P0 · 核心链路（上线前必须过）**
- 5 类卡片渲染正常、字段完整
- 选择题判定正确（选对 / 选错）
- 简答评分返回「分数 + 评语 + 反馈」
- 答完即过，不卡进度
- 连击状态机：连续 +1 / 断签重置 1 / 同日重复不计
- 重启服务后卡片 + 进度不丢

**P1 · 异常容错**
- DeepSeek 超时 / 报错 → 不崩溃，提示「稍后重试」
- API key 失效 → 明确报错，不白屏
- 断网 / 弱网 → 不崩，恢复后可用

**P2 · 内容质量 + 体验**
- 单卡 800–1000 字
- 出处标注率 100%
- 专业感（你抽 10 条人工过）
