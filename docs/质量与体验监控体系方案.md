# 微知 · 质量与体验监控体系方案

> 日期：2026-08-21 · 状态：方案稿（含自检结论）· 服务端：<服务器IP>

## 一、背景与目标

内容由 AI 批量生成（RSS 抓取 + 任务建卡），用户不可能人工盯质量。目标：**自动化「质量巡检 + 体验指标」**，定期产出 badcase 清单与使用日报，让「发现问题 → 修复 → 回流」不依赖人盯。

## 二、总体架构

```
服务器 cron 每天 3:00 跑 daily_check.py
├── ① 内容质量巡检（客观规则 + AI 打分）→ badcase 清单
├── ② 体验指标日报（现有数据 + 前端埋点）→ 波动信号
└── ③ 写报告 /opt/weizhi/app/quality_reports/YYYY-MM-DD.json

查看：网页「质检报告」入口（弹窗显示最近报告）+ 我每周汇总简报
```

## 三、模块一：内容质量巡检

### 3.1 客观规则层（脚本直算，零成本）

| 规则 | 判定 badcase |
|---|---|
| 字段缺失 | think_answer / quiz / review_quiz 缺失或 <150 字 |
| 题数不足 | quiz 少于模板要求（T1/T4/T5=2，T2/T3/T6=3）；review_quiz <3 |
| 疑似重复 | 同 template 同 title 出现 ≥2 次 |
| 字数异常 | 精读 body <600 字；代码直觉 <80 字 |
| 结构错误 | quiz 非数组 / answer 越界 / 字段类型不符 |

### 3.2 AI 主观打分层（DeepSeek 逐张评，temperature=0.2 保一致）

| 维度 | 查什么 |
|---|---|
| 准确性 | 事实错误（重点：T3 公式、T1 释义、T6 伪代码逻辑）|
| 相关性 | 内容是否切题 |
| 深度 | 是否泛泛而谈（只有定义没有例子/机制）|
| 结构 | 骨架字段是否按模板 |

**判定**：任一维度 ≤2 或综合 <3 → badcase，带理由（如「事实错误：XX 说反」「太浅：无例子」）。
**成本**：约 0.01-0.02 元/张；每天查 20 张 ≈ 0.4 元。

### 3.3 候选范围（覆盖全库，不遗漏老卡）

- **每天**：增量查「最近 48h 生成/更新的卡」+ 按 id 轮转补足 20 张（轮询机制保证老卡几天内也会被覆盖）
- **每周日**：全量兜底（全库一次扫完，约 200 张 ≈ 4 元/周）

## 四、模块二：体验指标日报

### 4.1 现有数据直接算（零改动）

| 指标 | 来源 | 信号 |
|---|---|---|
| 日学习量 | progress 表 | 波动大 = 节奏不稳 |
| 复习完成率 | queue vs reviews | <60% 标红 = 拖欠 |
| 复习正确率 | reviews.quality | 持续 <50% = 卡太难/没讲透 |
| 掌握率 | cards.mastered 占比 | 学过的记住了多少 |
| 连击 | user_state.streak | 中断 = 流失信号 |
| 到期遵守度 | next_review_at vs review_date | 到期当天复习还是拖 N 天 |

### 4.2 前端埋点（M2，加 4 个事件）

| 事件 | 含义 |
|---|---|
| think_open | 点「看 AI 回答」→ 思考题点开率 |
| open_submit | 提交简答 → 简答使用率 |
| calendar_open | 打开日历 → 打卡查看率 |
| search_use | 使用搜索 → 检索使用率 |

实现：reader.html 埋点 post `/api/event` → 后端写 events 表 → 日报统计。
**这个日报本身就是提醒器**：拖欠/断签/下滑都标红，不依赖人盯。

## 五、模块四：报告与查看

- **存储**：`quality_reports/YYYY-MM-DD.json`（保留最近 30 天，旧的自清理）
- **网页入口**：首页顶部/设置加「📋 质检报告」按钮 → 弹窗显示最近报告（badcase 清单 + 原因 + 建议 + 重生成按钮）
- **周报**：我每周读报告，整理成「本周质量简报」发用户（哪些 badcase、建议重生成哪些）

## 六、闭环走查（自检）

| 环节 | 是否闭合 | 说明 |
|---|---|---|
| 数据源 | ✅ | cards/progress/reviews/events 表都有 |
| 自动检测 | ✅ | cron 每天 3:00，不依赖人 |
| 报告产出 | ✅ | JSON 落盘 |
| 用户可见 | ⚠️ | **需新增网页报告入口（前端改动）** |
| 行动闭环 | ⚠️ | badcase 一键重生成需**先删旧卡**（防重复），当前重生成逻辑会 INSERT OR IGNORE 冲突 |
| 效果回流 | ✅ | 修复后下次巡检自然验证 |

## 七、自检发现的缺口与对策

| # | 缺口 | 对策 |
|---|---|---|
| 1 | 重生成会因 source_url 冲突失败（旧卡还在）| 重生成前先 `delete_card(旧 source_url)`，再走质量门禁重新生成 |
| 2 | 网页报告入口不存在 | M1 加 reader.html「质检报告」按钮 + 弹窗（读最近报告 JSON）|
| 3 | 报告文件累积 | 只保留最近 30 天，cron 里顺带清理 |
| 4 | 老卡质量查不到 | 轮询机制（id 轮转）+ 周日常规全量 |
| 5 | AI 打分误判 | temperature=0.2 保一致；badcase 带理由，用户看理由判断 |
| 6 | 埋点需新表 | events 表 + /api/event 接口（M2）|
| 7 | 波动阈值可能误报 | 阈值可配（config），默认复习完成率 60% / 正确率 50% |

## 八、Agent 演进路径（诚实定位）

当前是「**AI 流水线 + 反馈闭环**」：感知（抓取/巡检/判分）✅ 行动（生成/调度）✅，但**决策是固定规则**（SM-2、门禁阈值），没有「编排大脑」做自主目标迭代。

**要升级成真 Agent**：加 `daily_agent.py` 编排层——巡检发现 badcase → **自动重生成**（不等人批）；发现复习拖欠/学习下滑 → 自动调整提醒策略；只有「需要用户拍板」才停下。届时成为「自主管理学习系统的管家」，M1 的巡检脚本是其「感知+报告」骨架。

**2026-08-21 状态更新**：`daily_agent.py` 编排层已上线——ReAct 循环落地（读报告→规则信号→LLM 决策→执行修复→写程序内通知）。通知走「程序内推送」（铃铛+弹窗，未读自动弹出），不依赖 Web Push。按 ReAct 五要素对照：Action/Observation/Tools/Memory 已具备，Thought 一环由 daily_agent 的 LLM 决策补上——当前已是「管家 Agent」初版（决策自动化 + 程序内汇报），未来可升级：Web Push 主动推送、学习节奏自适应调整、目标层（用户设定目标后自主规划）。

## 十、成本与隐私

- **成本**：每天 20 张 AI 打分 ≈ 0.4 元 + 每周全量 4 元 ≈ **2 元/周**，可忽略
