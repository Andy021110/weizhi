# 微知 · 内容生产配方与 Golden Set

> 制定日期：2026-08-19 · 配套《学习计划与每日配额方案.md》
> 本文是 5 类卡片的「生产配方」总纲：每类怎么切、怎么生成、golden set 怎么定。
> 「skill」的落地形态 = 骨架（字段写死）+ 切片规则 + prompt + golden set。

---

## 一、设计思路：为什么这么切片

### 核心原则：切片单位 = 内容的「自然原子单元」

每种内容的「天然单元」不同，切片不是人为切碎，而是「找到这个自然单元，按规模档取 N 个，按依赖排序」。

| 类型 | 自然单元 | 为什么这是「一张完整卡」 |
|---|---|---|
| T1 词汇 | 词 | 音标/释义/例句/易错点，一个词天然讲得完整 |
| T2 精读 | 篇 | 一篇文章的正文 + 题 + 思考，天然完整 |
| T3 数学 | 概念 | 直觉 + 公式 + 例题 + 自测，天然完整 |
| T4 通识 | 知识 | 一个冷知识/现象，天然独立 |
| T5 技能 | 模块 | 一个动作/步骤组，天然完整 |

### 三条铁律

1. **原子单元 = 1 卡，且每卡自带「学+练+思考」**（正文 + quiz + 思考题）→ 一张卡本身就是一个完整学习周期，不需要拆成「导入+主体+收尾」的伪 5 卡结构（那会导致碎片化、也和现有 prompt 冲突）。
2. **组 = 进度里程碑**（制造「小完成感」），不是内容结构。词汇 10 词一组（背词最小有效批量），其余 5 个一组（一个专题的里程碑）。
3. **规模档 20/50/100 = 每批生成多少原子单元**，给 AI 一个明确的「切片预算」，让它从「自由发挥」变成「在预算内填空」。

### 为什么规模档是 20/50/100

- 都是 10 的倍数 → 同时整除 T1 的「10 词/组」和其余类型的「5 个/组」，不切半组。
- 按每天 3 卡 → 20≈1 周、50≈2-3 周、100≈1 月，落在「完成感区间」。
- 上限 100，更大主题靠「续学」滚动，避免一次生成超时。

## 二、5 类生产配方

### T1 词汇（t1_vocab）
- **骨架字段**：word / phonetic / pos / pos_label / definition_cn / etymology / examples[] / common_mistake / quiz[] / **think_question / think_answer**（无 open_question）
- **切片**：1 词 = 1 卡；10 词 = 1 组；排序按频次/难度
- **Golden set 规范**：① 站在中文母语者视角讲「易混点/误用」；② 例句必须是母语者真实会说的话；③ 主动辨析近义词；④ **AI 缩写（RAG/RLHF/PMF）按缩写本义解释，不按字母拆分翻译**

### T2 精读（t2_reading）
- **骨架字段**：summary / body(800-1000字) / core_points[] / think_question / **think_answer** / quiz[] / open_question{}
- **切片**：1 篇 = 1 卡；5 篇 = 1 组；排序按主题序
- **Golden set 规范**：① 忠实原文不篡改；② 多主题文章只聚焦主标题相关小节；③ 出处标注 100%

### T3 数学（t3_math）
- **骨架字段**：intuition / example / try_it / quiz[] / **think_question / think_answer / open_question{}**
- **切片**：1 概念 = 1 卡；5 概念 = 1 组；排序**严格按先后依赖**（概念链）
- **Golden set 规范**：① 先直觉类比后公式，不吓跑怕公式的人；② 强调现实应用；③ 例题/题都能心算或简单推理；④ 简答题要求「用自己的话复述概念」

### T4 通识（t4_trivia）
- **骨架字段**：hook / body(600-800字) / fun_facts[] / share_line / quiz[] / **think_question / think_answer**（无 open_question）
- **切片**：1 知识 = 1 卡（**纯散卡，无组、无计划**）
- **Golden set 规范**：① 先抛钩子再讲原理；② 面向成年人讲「为什么」；③ 可传播、有画面感；④ 思考题考「现实启示」

### T5 技能（t5_skill）
- **骨架字段**：summary / steps[] / bad_example / good_example / tip / try_it / quiz[] / **think_question / think_answer / open_question{}**
- **切片**：1 模块 = 1 卡；5 模块 = 1 组；排序由浅入深
- **Golden set 规范**：① 步骤可执行、含示例；② 有正反例对照；③ quiz 用「步骤顺序/正误判断」题；④ 「今天就试」的行动提示；⑤ 简答题要求「设计应用场景」

### T6 代码/算法理解（t6_code）
- **骨架字段**：summary / intuition / pseudocode（伪代码） / key_steps[] / why / example / pitfalls / quiz[] / review_quiz[] / think_question / think_answer / open_question{}
- **切片**：1 算法/代码模块 = 1 卡；5 模块 = 1 组；排序由浅入深/依赖序
- **定位**：不是逐行解读真实源码（AI 无真实仓库），而是「代码/算法理解」——用直觉 + 伪代码 + 例子讲清核心思想，类似 T3 数学的概念直觉，对象换成代码
- **Golden set 规范**：① 先直觉类比后伪代码；② 伪代码含中文注释、贴近真实、10-20 行；③ 讲清「为什么这么设计」（对比朴素方案）；④ 给例子走一遍流程；⑤ 简答题要求「用自己的话讲算法怎么工作」

## 三、Golden set 的用途与落地

**两个用途：**
1. **生成时 few-shot 喂 AI**：把 3-5 个标准样例塞进 prompt，让 AI「照葫芦画瓢」，而不是从零发挥（稳定性来源）。
2. **验收时作标尺**：生成结果和 golden set 比对结构（字段/顺序/字数），不一致则重生成该卡。

**落地状态：**
- ✅ 已导出 `golden_set.json`（5 类各 1 张代表卡，字段完整：正文 + quiz + review_quiz + think_question + think_answer + open_question）。
- ⬜ 后续：每类扩到 3-5 个样例（散卡 / 组 / 计划三种形态），优先 T3（概念链难稳）和 T5（步骤易流水账）。
- 样例来源：先批量生成 → 人工挑「结构完整、质量达标」→ 固化进 golden_set.json。

## 三·一、学习卡 vs 复习卡（两件事，务必区分）

用户明确：**随堂小测 ≠ 复习测验**，是两套独立体系。

| | 学习卡（学的时候） | 复习卡（复习的时候） |
|---|---|---|
| 考察点 | 「看懂没」 | 「记住没」 |
| 题源 | `quiz`（随堂）+ `think_question`（思考）+ `open_question`（简答） | `review_quiz`（变式题，生成时一并产出 3 道） |
| 触发 | 点进卡片即见 | 学过 → 按 SM-2 间隔（1/3/7/15/30 天）到期 → 复习队列 |
| 判分 | quiz 客观判分；open_question 调 AI 评分 | 规则判分（不调 AI，复习不花钱） |

**字段归属：** quiz/review_quiz 5 类都有；think_question/think_answer 5 类都有；open_question 仅 T2/T3/T5（记忆型/轻量型的 T1/T4 不做简答）。

## 四、切片与生成的完整链路（一次建计划发生什么）

```
用户选类型 + 主题 + 规模档(N)
        ↓
① 出大纲：AI 按类型切出 N 个原子单元（词汇=词清单 / 数学=概念链 / 精读=篇目 / 技能=模块）
        ↓
② 大纲确认：用户可增删、调序
        ↓
③ 逐卡生成：每个原子单元按本类骨架生成 1 张卡（含 quiz + think + open + review_quiz）
        ↓
④ 落库：plan_id + plan_index（全局序）+ group_index（组序）+ batch_index（批次）
        ↓
⑤ 首页：任务卡（封面）→ 点进去翻卡学习，**一次翻完整组**（词汇 10 词 / 其余 5 个），翻完弹「本组完成」
```
