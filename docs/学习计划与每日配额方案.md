# 学习计划与每日配额方案

> 对齐日期：2026-08-18 / 08-19 · 状态：任务切片体系已补全，待实施
> 本文是「微知」从资讯流升级为学习系统的产品宪法，后续开发以本文为准。

---

## 一、背景与问题

**现状（两个真问题）：**
1. **内容太散**：每天 cron 抓 RSS → 生成散卡，本质是「资讯流」，没有连续性学习路径。用户想系统学一个东西（雅思 3600 词 / RAG / Transformer 源码级）时，无法「分天推进、续学、断学提醒」。
2. **API 无上限**：pipeline.py 每天抓所有 RSS 源的所有文章，没有生成上限，源越多 API 烧越快。

**用户诉求（对齐后）：**
- 大任务拆成 N 张卡，分天学，第二天优先续学
- 有特殊标识（进度徽章），断学超时高亮提醒
- 每天卡片数量有硬上限，防止无限耗 API

---

## 二、核心概念：散卡 vs 任务（边界澄清）

**散卡 ≠ 任务**，这是两套东西：
- **散卡**：不算任务，学完即过，不追踪、不复读、不进计划。
- **收藏 = 留档**：收藏的卡只是「存起来以后翻」，不进入复习队列（散卡不复习）。
- **任务**：分两层，统一用 **Plan（计划）** 数据模型表达。

| 层 | 名称 | 触发方 | 时长 | 示例 |
|---|---|---|---|---|
| 1 | **短期任务** | **系统推荐**，用户确认「添加」才生效 | 3-15 天 | 「3 天搞懂 RAG」 |
| 2 | **学习计划** | **用户主动创建** | 自定义（长期） | 雅思 360 卡 / RAG 40 卡 |

任务用字段区分：
- `source`: `user`（用户主动）/ `system`（系统推荐）
- `duration`: `short`（3-15 天）/ `long`（自定义）

**关键：推荐 ≠ 添加**。系统推荐短期任务后，用户点「准备学」才提醒，确认「添加」才变成进行中任务。

## 三、每日配额模型（已对齐，硬规则）

**新卡配额**（重，读正文 + 完整答题）：

| 场景 | 每日新卡量 |
|---|---|
| 无计划 | ~10 张散卡 |
| 单计划 | 该计划节奏档（1-5 卡，默认 3） |
| 多计划并行 | Σ各计划节奏档，但**总 ≤15**，按「续学优先 + 创建顺序」轮转 |
| **硬上限** | **≤ 15 张/天** |
| **并发上限** | **≤ 5 个同时进行**的计划/任务 |
| **生成上限** | pipeline 每天最多生成 ≤15 张新卡 |

**复习卡配额**（独立，轻，快速回忆 + 1-2 题）：≤ 30 张/天，不占新卡配额。

**配额原则：**
- 15 张 × 5-10 分钟 ≈ 2 小时，已超碎片时间，故封顶。
- 有计划时，推荐量以「计划任务量」为轴放大（计划卡 : 配套散卡 ≈ 1:1 为 ×2，1:2 为 ×3）。
- 短期任务占用并发额度（统一算在 5 个里），避免用户同时追太多线。
- 多计划分配：总新卡超 15 时，按「续学优先（断学最久的先发）→ 创建顺序」轮转，每计划实际发卡 = min(该计划节奏档, 剩余配额)。
- 生成上限与硬上限一致（15 张），从源头卡住 API 消耗。

## 四、学习计划系统设计（v2，2026-08-19 对齐）

### 三层模型
| 层 | 定义 | 完成感 |
|---|---|---|
| 卡 | 原子单元：1 词 / 1 篇 / 1 概念 / 1 知识 / 1 模块（每卡自带学+练+思考，本身即一个完整学习周期） | 单卡 |
| 组 | 进度里程碑：每 5–10 个原子单元一组，学完一组触发「小完成」 | 小完成 |
| 计划 | 学习目标：若干组，按规模档分批生成 | 大完成 |

### 两个正交档（替代旧的「总卡数/每天推进量」）
- **规模档**（每批多少卡 = 多少原子单元）：20 / 50 / 100，控制「学多少内容」
- **节奏档**（每天发几张）：1–5，默认 3，控制「学多快」
- **总时长 = 规模 ÷ 节奏**，自动算，用户不选天数

### 规模档（3 档，独立推导）
| 档位 | 卡数=原子单元数 | T1（词） | T2/T3/T5（篇/概念/模块） | 时长(每天3卡) |
|---|---|---|---|---|
| 轻量 | 20 | 20 词=2组 | 20 个=4 组 | ~1 周 |
| 标准 | 50 | 50 词=5组 | 50 个=10 组 | ~2–3 周 |
| 深度 | 100 | 100 词=10组 | 100 个=20 组 | ~1 月 |

推导依据：① 一批时长落在 1 周~1 月「完成感区间」；② 卡数是 10 的倍数（同时整除 T1 的 10 词组、其余类型的 5 个组，不切半组）；③ 只 3 档避免选择过载；④ 上限 100，更大主题靠「续学」滚动（避免一次生成超时）。

### 5 类切片规则（固定，AI 不判断）
| 类型 | 原子单元 = 1 卡 | 1 组 | 排序/依赖 | 是否做计划 |
|---|---|---|---|---|
| T1 词汇 | 1 词 | 10 词 | 频次/难度 | ✅ |
| T2 精读 | 1 篇 | 5 篇 | 主题序 | ✅（单篇=散卡亦可） |
| T3 数学 | 1 概念 | 5 概念 | 严格依赖序 | ✅ |
| T4 通识 | 1 知识 | 无 | 无 | ❌ 纯散卡 |
| T5 技能 | 1 模块 | 5 模块 | 由浅入深 | ✅ |

> **关键修正（08-19）**：原子单元 = 1 卡（与现有 prompt「1 篇/1 概念/1 模块 = 1 卡」一致），组是「进度里程碑」而非「1 主题拆 5 卡」。此前误写「1 篇=5 卡」会让规模档实际内容量差 5 倍，已更正。

### 生产配方（每类一份，稳定性来源）
① **骨架**（卡字段写死）② **三态模板**（散卡/组/计划）③ **Golden set**（每种形态 3-5 个手工验证样例，两个用途：生成时 few-shot 喂 AI「照葫芦画瓢」、验收时作标尺比对结构）④ **Prompt 约束**（字段白名单+字数范围+禁止项）⑤ **素材规则**（要什么素材/去哪找/什么格式）⑥ **校验规则**（生成后逐字段校验，缺则重生成该卡）

### 四机制（保留）
1. **拆解**：选类型+主题 → 估算原子单元数 → 出大纲（按序清单，用户可增删调序）→ 按规模档分批生成。
2. **续学优先**：第二天首页**优先**展示「进行中计划」的下一批。
3. **特殊标识**：卡片徽章「雅思 · 23/100」，计划卡与散卡视觉区分（顶部色条）。
4. **搁置高亮**：超过 X 天（默认 3 天）没学，首页提示 + 计划卡标黄/红。

## 四·四、用户操作场景全生命周期应对方案（Golden set 来源）

> 每个场景对应一条硬规则，将来做成 golden set / prompt 约束，指导 AI 生成与切片。这是本方案覆盖「各种用户操作与计划设计」的验收清单。

### A. 创建阶段
| 场景 | 应对方案 |
|---|---|
| 从预设库一键创建（雅思/六级/线性代数/Obsidian/SQL/世界史） | 预设库自带「类型+主题+推荐规模档+人工验证大纲」，点即走，不现场切 |
| 自定义精确主题（如「背 20 个机器学习术语」） | 用户已给原子单元数 → 直接按规模档生成，跳过估算 |
| 自定义模糊主题（如「学学机器学习」） | AI 先估算规模 → 回显「约 40 主题，建议 50 卡档」→ 用户确认/调档 |
| 超大主题（雅思 3000 词） | 自动判定「总量>规模档」→ 出大纲切成批次串 → 先生成第 1 批，学完「续学」 |
| 类型选错（把「读文章」选成词汇） | 建计划前给「类型预览」；生成后发现错 → 允许改类型重生成 |
| 大纲不满意 | 大纲确认页支持增删原子单元、拖拽调序、改分组 |

### B. 学习阶段
| 场景 | 应对方案 |
|---|---|
| 每天发卡节奏 | 从进行中计划按「续学优先」取卡，直到当日新卡配额（≤15）用尽 |
| 某天不想学 | 「跳过今天」→ 不打卡、计划进度不动 |
| 想突击 | 临时调高节奏档（3→5），仅影响之后发卡，不追溯 |
| 中途改规模档/节奏档 | 计划详情页可改；改规模档=改后续批次生成量，已生成卡不动 |
| 多计划并行 | 并发上限 ≤5，超出提示「先暂停一个再新建」 |
| 卡太难/太简单 | 卡上反馈 → 简单卡跳过复习，难卡降难度重生成 |
| 卡质量差/事实错 | 「重新生成」单卡重生成；连续差 → 标记该类型 golden set 需补 |

### C. 组/批完成阶段
| 场景 | 应对方案 |
|---|---|
| 学完一组 | 触发「小完成」庆祝 + 该组卡进入复习队列（SM-2） |
| 学完一批 | 触发「大完成」庆祝 + 弹「续学下一批 / 结束」 |
| 续学 | 按同一规模档生成下一批，进度续接（100→200） |
| 不续学 | 计划标「已完结」，已学卡继续走复习 |

### D. 中断/放弃/管理
| 场景 | 应对方案 |
|---|---|
| 中途放弃 | 已学卡保留复习，未学卡归档，计划移入「已放弃」 |
| 暂停 | 停止发新卡，到期复习仍提醒（可设一并暂停） |
| 恢复 | 从上次位置续发 |
| 删除 | 二次确认；已学卡保留（去计划化），未学卡删除 |
| 编辑已生成卡 | 手动改标题/正文/题，改后标「已编辑」不再被 AI 覆盖 |

### E. 复习阶段
| 场景 | 应对方案 |
|---|---|
| 复习卡与新卡关系 | 复习独立配额（≤30），不占新卡（≤15） |
| 复习撞车 | 当日可延后 20% 复习到明天（标「已延后」+ 明天优先） |
| 某卡反复错（leech） | 连续错 3 次 → 标 leech 暂停复习，建议重学/删除 |

### F. 散卡与计划的关系
| 场景 | 应对方案 |
|---|---|
| 散卡升级成计划 | 某主题散卡攒到 ≥5 张 → 提示「整合成计划」，AI 补齐大纲 |
| 计划内某卡想单独收藏 | 收藏=留档，不影响计划进度与复习 |

## 四·五、复习机制（SRS 间隔重复，已定稿）

**核心**：每张卡学完进入「复习时间轴」，用 SM-2 间隔重复对抗遗忘曲线。

- 复习间隔：第 1 天 → 3 天 → 7 天 → 15 天 → 30 天，逐次拉长，直到「已掌握」归档。
- 反馈：答对 → 间隔拉长；答错 → 回退到 1 天。

**复习门槛（旧的不去新的不来）**：
- 每天先完成到期复习卡，复习完才解锁新卡（Anki 复习门槛）。
- **柔性口**：当日可延后 20% 复习卡到明天（标「已延后」+ 明天优先），避免复习撞车卡死。

**两份独立配额**（复习和新卡不互相挤占）：
- 新卡：≤ 15 张/天（重，读正文 + 完整答题，5-10 分钟/张）。
- 复习卡：独立 ≤ 30 张/天（轻，快速回忆 + 1-2 道题，30 秒-1 分钟/张）。
- 理由：复习量 ≈ 新卡量 × 5（每张卡复习约 5 次），若共用配额会挤死新卡（长期新卡只剩 2-3 张/天）。**30 的推导**：节奏档上限 5 卡/天 × 5 次复习 = 25 张，加答错回退余量 → 取 30，否则节奏档 5 卡时复习会堆积、卡死新卡。

**复习出新题（变式题池，避免背答案）**：
- 生成卡时一次性产出「学习题（当堂作业）」+「变式复习题池（小考，3-5 道，不同角度）」。
- 复习时从题池轮换抽题 + 打乱选项顺序，不打背答案、复习时不调 AI。

**5 类复习模板**（规则判分）：

| 类型 | 复习测试 | 判分 | 耗时 |
|---|---|---|---|
| T1 词汇 | 英译中/中译英 选择题 | 规则 | 20-30 秒 |
| T2 精读 | 理解型选择题 | 规则 | ~1 分钟 |
| T3 数学 | 心算/推理选择题 | 规则 | 30-60 秒 |
| T4 通识 | 判断/选择题（轻） | 规则 | 20-30 秒 |
| T5 技能 | 步骤顺序/正误选择题 | 规则 | 30-60 秒 |

题型配比做成可配置项。

**简答与思考题增强**：
- 简答评分更详细：`reference_answer` 200-300 字、`grading_points` 3-4 个详细点、`comment` 写详实；评分后展示「评分要点 + 你的答案 vs 参考」对照。
- 思考题加「看 AI 专业回答」按钮：点一下调 AI 生成结构化详尽回答（观点 + 论据 + 延伸，300-500 字），生成一次后缓存。

**完整日常循环**：打开 → ①复习门槛 → ②新卡学习（任务续学优先 + 散卡填充）→ ③打卡连击 → ④系统排期 → 明天循环。

## 五、数据层改动

```sql
-- 新增 plans 表
CREATE TABLE plans (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  title TEXT,            -- 计划名
  topic TEXT,            -- 主题（如 RAG）
  source TEXT,           -- user / system
  duration TEXT,         -- short / long
  total_cards INTEGER,   -- N
  cards_per_day INTEGER, -- 每天推进量，默认 3
  status TEXT,           -- active / paused / done
  created_at TEXT,
  last_studied_at TEXT   -- 判断搁置
);

-- cards 表加字段
ALTER TABLE cards ADD COLUMN plan_id INTEGER;
ALTER TABLE cards ADD COLUMN plan_index INTEGER;  -- 该卡在计划中的序号
ALTER TABLE cards ADD COLUMN plan_total INTEGER;  -- 计划总卡数（徽章显示 N/total）

-- cards 表加复习字段
ALTER TABLE cards ADD COLUMN memory_state TEXT;     -- new / learning / mastered
ALTER TABLE cards ADD COLUMN next_review_at TEXT;   -- 下次复习时间（NULL=不复习）
ALTER TABLE cards ADD COLUMN review_count INTEGER DEFAULT 0;
ALTER TABLE cards ADD COLUMN ease REAL DEFAULT 2.5; -- SM-2 难度系数
ALTER TABLE cards ADD COLUMN interval_days INTEGER DEFAULT 0;

-- 新增 reviews 表（复习日志）
CREATE TABLE reviews (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  card_id INTEGER,
  review_date TEXT,
  result TEXT,            -- again / hard / good
  interval_before INTEGER,
  interval_after INTEGER
);
```

`user_state` 存计划的汇总进度（已学张数、最近学习日）。

## 五·五、成本预估

DeepSeek `deepseek-chat`（v4-flash 非思考）现价：输入 ¥1/百万 tokens，输出 ¥2/百万 tokens。

| 项目 | 单张成本 |
|---|---|
| 资讯卡（T2 精读，最贵） | 约 1.4 分（入 9000 + 出 2500 tokens） |
| 轻量卡（T1/T3/T4/T5 按需） | 约 0.2 分（入 500 + 出 800） |
| 复习卡（规则判分） | 0 元（复用 quiz，不调 AI） |
| 复习卡（简答 AI 评分，可选） | 约 0.1 分 |
| 配图（SiliconFlow Flux） | 5 分/张 |

**每日 AI 成本约 ¥0.2-0.3，每月约 ¥7-15 元（配图则 ~¥15）。服务器 ¥28-56/月才是大头。** AI 成本不是问题，配每日上限更多是为了阅读体验不被淹没。

## 六、分阶段实施

|---|---|---|

## 八、产品走查结果（两轮，2026-08-18）

### 第一轮：8 个遗漏点 + 方案（业界对标）

| # | 遗漏点 | 业界参考 | 方案 |
|---|---|---|---|
| 1 | 冷启动+空状态 | 多邻国选目标、墨墨选词书 | 首次三步引导（选偏好→建不建计划→定每日量）；空状态给引导页 |

| 5 | 答错当天重做 | Anki/墨墨当天重复 | 答错进「今日再练」队列，当天稍后再出；二次错回 1 天 |
| 6 | 数据统计 | Anki 统计页、多邻国连胜 | 轻量统计页：累计天数/连击/总卡数/记忆保持率/今日进度（无排行榜） |
| 7 | 搜索+收藏浏览 | Anki 搜索 | 「收藏/已学」列表页 + 关键词搜索 |
| 8 | 简答评分透明度 | 评分标准公示 | 展示「评分要点 + 你的答案 vs 参考」对照 |

### 第二轮：新发现的遗漏（更深的边界）

| # | 遗漏点 | 严重度 | 方案 |
|---|---|---|---|
| 1 | **安全问题：reader 无鉴权** | 🔴 高 | 现在绑 0.0.0.0:8000 无密码，任何知道 IP 的人都能访问/操作/刷 API。需加访问口令（URL token 或简单登录） |
| 2 | **卡片编辑能力** | 🔴 高 | AI 生成的卡可能有事实错误，需支持手动编辑（改标题/正文/题） |
| 3 | **任务拆解的确认** | 🟡 中 | AI 拆大纲后是否让用户预览/调整？建议半自动：先预览大纲、可删改、再批量生成 |
| 4 | **任务完成的判定** | 🟡 中 | 学完 N 张 = 完成，还是复习到掌握才算完成？建议：学完即「完成」，复习是独立长期巩固 |
| 5 | **复习的手动操作** | 🟡 中 | 「标记已掌握」（跳过后续复习）、「跳过今天」——给用户控制权 |
| 6 | **难度字段的用途** | 🟡 中 | difficulty（入门/中级/进阶）现有字段没用起来，可决定复习间隔基数 |
| 7 | **每日生成失败兜底** | 🟡 中 | pipeline 挂了今天没新卡，前端给「今天暂无可学，去复习或逛收藏」降级 |
| 8 | **时区/日期一致性** | ⚪ 低 | 复习「到期」按天，服务器已改 Asia/Shanghai，前端也按本地时区算，避免跨天错位 |
| 9 | **数据备份** | ⚪ 低 | SQLite 定期备份（自用数据珍贵） |
| 10 | **内容质量反馈** | ⚪ 低 | AI 生成错卡，用户反馈 → 重新生成/删除 |

### 结论
产品方案已覆盖：散卡/任务/复习/配额/5 类模板/成本/两轮走查遗漏。**最需优先补的是「鉴权」和「卡片编辑」两个 🔴 项**，其余在 P1-P3 实现时一并处理。
