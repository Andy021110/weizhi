# 第一部分：主题类型自动识别（解决「不该由用户选类型」）

## 问题

建任务时让用户手动选「词汇/精读/数学/通识/技能/代码」，但用户可能归错类（如「学习 Agent」误选词汇模板）。用户不该承担「判断知识类型」的认知负担。

## 方案：AI 自动判断类型（与消歧合并成「主题理解」一步）

### 流程改造

```
现在：用户输主题 → 手动选类型 → 出大纲
改为：用户输主题 → AI 自动判断「类型 + 方向歧义」→（有歧义才弹确认）→ 出大纲
```

### 后端新增 classify_topic（复用消歧的 AI 调用模式）

输入主题 → 输出：
```json
{
  "template": "t2_reading",       // AI 判断的类型
  "label": "精读",
  "reason": "Agent 范式是概念性内容，适合精读",
  "has_ambiguity": true,          // 是否还需方向消歧（复用现有逻辑）
  "interpretations": [...]        // 有歧义时的候选方向
}
```

判断规则（写入 prompt）：
- 学一个词/术语 → t1 词汇
- 读文章/论文/概念/范式 → t2 精读
- 数学概念/公式/定理 → t3 数学
- 冷知识/通识/历史 → t4 通识
- 技能/操作步骤/方法 → t5 技能
- 代码/算法/程序机制 → t6 代码

### 前端改造

类型按钮区改为：
- **「✨ 自动」（默认选中）**：AI 判断类型
- 6 个手动类型按钮（想强制指定时才点，覆盖自动）

交互：用户输主题 → 点生成 → 「自动」模式下先 classify（判断类型）→ 再 disambiguate（方向消歧）→ 出大纲。手动模式则跳过 classify。

### 自检发现的关键点

1. **「学习 Agent」这类跨界主题**：可能是精读（概念）也可能是代码（算法循环）。classify 返回主类型 + 让用户可选次类型——但为避免复杂，v1 先让 AI 判断一个主类型，用户看大纲不满意可手动换类型重拆。
2. **类型判断本身会误判**：跟消歧一样，AI 判断非 100% 准。所以「自动」要**可感知**（显示「已识别为『精读』，可改」），不是黑盒。
3. **复用**：classify 和 disambiguate 可共用一次 AI 调用（一次返回类型+歧义），省一次调用。

## 目标

每天自动巡检内容质量 + 产出体验日报，网页可查 + badcase 一键重生成。

cron 每天 3:30 跑（抓取 6:00 之前，避开；也避开用户活跃时段）

### AI 打分的成本与容错
- 20 张 × ~5s ≈ 100s（cron 单次 OK）；API timeout=60，单卡失败跳过不计

## 二、cron 配置

```cron
30 3 * * * cd /opt/weizhi/app && .venv/bin/python daily_check.py >> daily_check.log 2>&1
```

## 三、网页报告入口（前端）

- 后端加 `GET /api/report/latest`：读最新报告 JSON（找不到返回空）
- reader.html 顶部加「📋 质检」按钮 → 弹窗显示：badcase 清单（标题+问题+建议+重生成按钮）+ 体验指标 + 通过率

## 四、badcase 一键重生成（关键，最易踩坑）

- 后端加 `POST /api/regen`：{source_url} → 删旧卡 → 按原 template/topic/plan 字段重新生成（走质量门禁）
- 前端报告弹窗每条 badcase 带「重新生成」按钮

### 自检发现的 6 个疏漏 + 对策

| # | 疏漏 | 对策 |
|---|---|---|
| 1 | 🔴 **重生成后 source_url 变化**（新时间戳），卡会脱离原计划 | 重生成时**保留原 plan_id/plan_index/group_index/batch_index**，只换 source_url 去重 |
| 2 | 🔴 重生成需防并发重复（点两次生成两张）| 接口幂等：重生成中标记卡 status='regenerating'，期间禁点 |
| 3 | 🟡 AI 打分超时/失败 | 单卡 try/except 跳过，不计入 checked |
| 4 | 🟡 复习完成率口径 | 「到期当天复习」需精确匹配（review_date == next_review_at 当天）；口径写清：`当日复习数 / 当日到期数` |
| 5 | 🟡 报告接口权限 | /api/report 复用 access_token 鉴权，不裸奔 |
| 6 | 🟡 日报「今日学习量」含散卡还是只任务卡 | 统一口径：progress 表当日条数（含散卡+任务卡），文档写清 |
