# 微知验收与测试方案

> 制定日期：2026-08-18 · 配套《开发计划.md》《学习计划与每日配额方案.md》
> 每个阶段做完，按本文的「验收项 + 合格标准」测，全过才算该阶段完成。

---

## 〇、验收策略（总原则）

- **不穷举所有排列组合**，抓「主路径 + 高风险点」，其余靠「兜底机制」覆盖。
- **三层**：主路径（必测，5 类 × 任务/散卡走通核心链路）→ 高风险点（必测，变式抽题、依赖排序、续学不重复）→ 长尾（不测，靠字段校验 + 重生成兜底）。
- **验收目标**：大部分 case 过 = 短期使用体验 OK，够用即可，不追求零 bug。

---

## 一、验收总框架（四层）

| 层 | 问什么 | 合格线 |
|---|---|---|
| **功能验收** | 能不能用 | 功能点 100% 通 |
| **状态机验收** | 对不对 | 边界用例 100% 过 |
| **异常容错** | 挂不挂 | 超时/断网/非法输入不崩溃 |
| **体验验收** | 好不好 | 内容抽检 + 真机达标 |

**判定规则**：每个阶段的验收项全部通过 = 合格；有 1 项不过 = 打回修复，修完重测该阶段。

## 二、分阶段验收清单

### P0 · 鉴权 + 每日配额

| 验收项 | 测试方法 | 合格标准 |
|---|---|---|
| 鉴权拦截 | 无 key 直接访问 `/api/cards` | 返回 403 或跳转 |
| 鉴权放行 | 带 key 访问 | 正常返回数据 |
| 无感持久化 | 带 key 访问一次后，去掉 URL 里的 key 再访问 | 仍正常（localStorage 已存 token） |
| 生成上限 | 服务器跑一轮 pipeline | 生成 ≤15 张新卡 |
| 推送上限 | 调 `/api/cards` | 当天返回 ≤15 张 |

### P1 · 计划系统 + 卡片编辑

| 验收项 | 合格标准 |
|---|---|
| 建计划 | 输入主题 → AI 拆大纲 → 预览 → 确认 → 批量生成卡 |
| 大纲预览 | 能预览大纲、删改大纲项后再生成 |
| 续学优先 | 第二天首页优先显示「进行中计划」下一批 |
| 进度徽章 | 卡片显示「雅思 · 23/360」 |
| 卡片编辑 | 改标题/正文/题 → 保存 → 刷新不丢 |
| 状态机 | 计划状态 active→paused→done 流转正确 |

### P2 · 复习引擎（核心，重点测数学正确性）

| 验收项 | 合格标准 |
|---|---|
| 间隔拉长 | 连续答对：间隔 1 → 3 → 7 → 15 → 30 天递增 |
| 答错回退 | 答错：间隔回退到 1 天，连续答对次数归零 |
| 掌握归档 | 间隔达 30 天后 → 标记 mastered 归档 |
| ease 下限 | ease ≥ 1.3（SM-2 规则） |
| 复习队列 | 到期卡（next_review_at ≤ 今天）正确进队列 |
| 复习门槛 | 不完成复习，不推新卡 |
| 变式题 | 复习题 ≠ 学习题（不同角度，非原题） |
| 答错当天重做 | 答错的卡当天稍后再出一次 |
| 柔性延后 | 当日可延后 20% 复习卡，明天优先 |
| 手动操作 | 「标记已掌握」跳过后续复习；「跳过今天」生效 |

### P3 · 短期任务 + 统计 + 搜索

| 验收项 | 合格标准 |
|---|---|
| 短期任务推荐 | 系统推荐 → 用户点「准备学」→ 确认「添加」→ 变成进行中 |

| 收藏浏览 | 收藏列表能翻看留档的卡 |

### P6 · 任务切片体系

| 验收项 | 测试方法 | 合格标准 |
|---|---|---|
| 规模档生成 | 建计划选 20/50/100 卡档 | 生成对应张数卡（误差 0） |
| 5 类切片 | 分别用 T1-T5 建计划 | T1=1词1卡；T2=1篇1卡；T3=1概念1卡；T5=1模块1卡 |

| 组进度 | 学完一组 | 有完成反馈，组节点点亮 |

### P7 · 内容源换 AI + 变式复习题池 + 手机端

| 验收项 | 测试方法 | 合格标准 |
|---|---|---|
| RSS 可达性 | 服务器跑 `pipeline.py --fetch-only` | 6 个源都抓到文章，无报错 |
| 内容 AI 相关 | 看抓到的文章标题 | 都是 AI/LLM/模型相关，不是泛科技 |
| 散卡生成质量 | 跑一轮 pipeline 生成几卡 | T2 精读卡字段完整、内容 AI 相关 |
| review_quiz 生成 | 生成一张卡看字段 | 有 review_quiz（3 道变式题，角度不同于 quiz） |
| 学习用 quiz | 学习时做题 | 做的是 quiz（随堂小测） |
| 复习用 review_quiz | 复习时做题 | 做的是 review_quiz（不同题，不背答案） |
| 抽题打乱 | 多次复习同一卡 | 每次抽的题/选项顺序不同 |
| 复习不调 AI | 复习时看日志 | 规则判分，复习不调 AI |
| 小米加到桌面 | 小米 Chrome「添加到主屏幕」 | 桌面有微知图标，点开全屏无地址栏 |

## 三、贯穿性验收（每个阶段都测）

| 项 | 合格标准 |
|---|---|
| 数字同源 | 连击/进度/复习状态，刷新前后一致，不丢 |
| 异常降级 | AI 超时/断网/返回异常 → 提示「稍后重试」，不白屏 |
| 持久化 | 重启 reader / systemd 后，卡片 + 进度 + 复习状态不丢 |
| 热更新 | 后端/前端改动 → 刷新即生效，无需重装 |

## 四、测试方法（本机 vs 服务器）

- **本机能测**：功能、状态机、异常容错（本地起 reader + 浏览器，可全测）。
- **需服务器**：鉴权（公网拦截）、真机蜂窝网体验（首屏 <3 秒）。
- **SM-2 数学**：写一组单元测试脚本，喂「连续答对/答错/交叉」用例，断言间隔序列，避免手测漏边界。
