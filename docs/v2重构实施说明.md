# 微知 v2 重构实施说明

## 当前已完成的垂直切片

- 非破坏性 `v2_` SQLite 表；
- Goal、Milestone、Source、EvidenceClaim、LearningPack、CardSpec、CardVersion、LearningState、Assessment；
- 一至三卡的 Pack 门禁；
- 事实句证据引用和数字一致性检查；
- 候选版本到 active 的发布过程；
- 用户修订生成新版本，发布后保留 concept 级学习记录；
- 完成卡片后创建 concept 级学习状态；
- 60–120 分钟每日调度，先预留复习，一天最多两个新 Pack；
- `/api/v2` 目标、来源、学习包、今日安排、完成与复习接口；
- `/v2` 新前端入口；
- 固定 Harness 三卡演示脚本。
- `verified-claims.json` 导入器会重新执行快照片段与数字核验，不直接信任上游状态。
- Pack Planner 可把已导入的 supported claims 规划成 1–3 张候选卡；同一目标和证据组合保持幂等。
- 单一薄弱事件不会单独成卡；当前价值门禁要求一个候选包至少包含两条相关核验证据。
- 资料库可直接发起规划，候选包支持预览、人工发布或拒绝。
- Source Processor 可处理网页、论文和 PDF：限制 15MB，保存原始文件与清洗正文快照，并记录每次处理的状态和失败原因。
- 处理器拒绝本机和内网地址；公网域名可通过桌面环境的受控网络出口抓取。
- 确定性 claim 抽取会过滤代码、参数表、正文残片和章节导航语，再按解码、输入、内存、评测、安全等主题聚类。

## 启动

```bash
cp config.example.json config.json
python scripts/seed_v2_demo.py
python reader.py
```

访问 `http://localhost:8000/v2`。旧版仍在 `/`；配置 `ui_version=v2` 后新版成为根页面。

## API

### 创建目标

```json
POST /api/v2/goals
{
  "outcome": "理解 Agent Harness 并能比较架构取舍",
  "current_level": "了解 LLM 和 Tool Calling",
  "use_context": "Agent 产品和工程设计",
  "daily_minutes": 90,
  "milestones": ["建立心智模型", "理解真实系统", "完成迁移设计"]
}
```

### 添加来源

```json
POST /api/v2/sources
{
  "source_type": "article",
  "canonical_uri": "https://example.com/article",
  "title": "文章标题",
  "status": "pending"
}
```

### 今日安排

`GET /api/v2/today` 默认使用最近活跃 Goal 的 `daily_minutes`；也可用 `?minutes=90` 临时覆盖。

### 创建与发布学习包

内部 evidence workflow 调用 `POST /api/v2/packs` 写入 candidate；通过门禁后调用 `POST /api/v2/packs/publish`。普通用户前端不直接拼装卡片 JSON。

已有资讯 workflow 项目可先导入证据：

```bash
python scripts/import_v2_evidence.py /path/to/workflow-project
```

演示学习包的配图由 `scripts/generate_v2_diagrams.py` 确定性生成。每张卡至少包含 2 张与学习目标对应的图，并必须提供 alt、图注和读图结论。Pack 页与证据区均保留可点击的原始信源。

## 回滚

本阶段没有删除或改写 v1 表。把 `config.json` 的 `ui_version` 改回 `v1`，即可恢复旧首页。v2 数据保留在 `v2_` 表中，不影响 v1 API。
