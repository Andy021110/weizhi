# 微知 v2 后续开发方案

> 文档状态：执行基线
>
> 更新时间：2026-09-10
>
> 适用范围：微知 v2 的目标规划、信源处理、学习包生产、学习与复习闭环

## 1. 这次重构要解决什么

微知 v2 的目标不是持续生产更多卡片，而是帮助用户在每天 1–2 小时的总学习时间里，利用多个 5–10 分钟片段获得可以复述、迁移和验证的知识。

系统最终应形成以下闭环：

```text
用户能力目标
  → 可验证的阶段目标
  → 可信材料与证据
  → 一目标一卡的学习包
  → 5–10 分钟学习
  → 即时练习与延迟回忆
  → 更新能力状态
  → 规划下一个学习包
```

成功标准不是“每天生成多少卡”，而是：

1. 卡片是否覆盖明确的学习目标；
2. 关键事实是否能追溯到信源；
3. 用户在延迟复习时是否能正确回忆和迁移；
4. 系统是否能根据学习结果调整后续内容；
5. 整条链路失败时是否可以定位、重试和回滚。

## 2. 从基本事实重新推导

### 2.1 已确认、无法绕开的事实

- 一篇文章可能包含多个命题，也可能没有值得学习的命题。
- 卡片的学习价值来自目标、解释、证据和练习之间的对应关系，不来自固定字数。
- 用户的单次碎片时间约为 5–10 分钟，每日总预算约为 60–120 分钟。
- 大模型输出存在幻觉、遗漏限定条件、数字改写和风格同质化风险。
- 配图只有帮助用户建立结构、比较关系或理解变化时才有价值。
- 即时答对不能证明长期掌握，必须观察延迟回忆和迁移表现。
- 自动发布会放大低质量内容，因此生产与发布之间需要质量门禁。

### 2.2 尚未被验证的假设

- 每张卡固定 800–1000 字最合适。
- 每张卡固定三道随堂题和三道复习题效果最好。
- 每篇文章拆成两三张卡就一定有价值。
- 每张卡放两张图就能提升理解。
- 七条预设路径适合长期保留为所有用户的固定路径。
- 规则规划器和通用模板足以长期生产高质量内容。
- 来源权威就意味着其中每个命题都适合当前用户学习。

这些假设只能通过真实学习实验判断，不能继续写成不可调整的产品规则。

### 2.3 真正目标

微知应成为“以能力目标为中心、以证据为边界、以回忆结果驱动下一步”的个人学习系统。

用户自建学习目标应保留，但输入表单只是起点。系统需要通过追问将模糊愿望变成：

- 目标能力；
- 当前水平；
- 使用场景；
- 成功证据；
- 前置知识；
- 里程碑；
- 每日时间预算。

### 2.4 现实资源与约束

- 当前技术栈是 Python、SQLite 和无构建原生前端。
- v1 仍在运行，v2 必须保留独立表和快速回滚能力。
- DeepSeek 可承担文本生成；图片服务需要通过可替换的 Provider 接口接入。
- 当前已有信源快照、证据门禁、候选发布和基础学习状态。
- 成本需要适合单用户自托管，模型调用必须缓存、幂等且可降级。
- 真实学习效果至少需要 7 天数据才能得到初步判断。

## 3. 当前基线

### 3.1 已实现

- v2 独立数据模型：Goal、Milestone、Source、EvidenceClaim、LearningPack、CardSpec、CardVersion、LearningState、Assessment。
- 目标创建、暂停和切换；每日 60–120 分钟预算。
- 七条学习路径及三卡启动包演示数据。
- 网页、论文和 PDF 抓取；原始文件与清洗快照保存。
- 下载大小、超时、内网地址和私有 IP 防护。
- 确定性证据抽取；代码、表格、残句和导航文字过滤。
- 至少两条相关核验证据才允许规划候选学习包。
- 规则规划器将相关证据聚合成一至三张卡。
- 候选包预览、发布和拒绝；信源链接可直接跳转。
- 卡片正文、两张确定性配图、随堂题与学习完成记录。
- 今日学习预算和到期复习后端接口。
- 现有自动化测试全部通过。

### 3.2 部分实现

- 七条路径只有启动包，尚未按掌握情况持续生成。
- 卡片正文达到阅读长度，但自动卡仍有明显模板感。
- 每卡有两张图，但图形语法以流程图为主。
- 复习调度后端已存在，前端流程和数据反馈未闭环。
- AI 资讯 workflow 可以导入证据，尚未成为 v2 内部的持续发现任务。
- 代码仓库和个人笔记在界面中可选，但没有专用解析器。

### 3.3 未实现

- 通过模型追问和完善 GoalSpec。
- 在严格证据边界内进行中文教学重写。
- 根据概念选择图形类型并调用 AI 生图。
- 对题目覆盖率、歧义率和答案泄露进行自动评测。
- CardVersion 差异预览和逐段修订。
- 完整的延迟复习前端与自适应路径更新。
- 三篇文章 A/B 实验和 7 日真实学习实验。
- v2 默认切换、生产认证、监控、备份与正式部署。

## 4. 目标架构

### 4.1 确定性边界

以下职责必须由程序完成：

- URL 和文件安全检查；
- 原始快照、哈希和版本保存；
- 证据片段定位；
- 数字、单位和引用一致性检查；
- 幂等键、缓存、重试与状态机；
- 卡片数量、学习时长和发布状态门禁；
- 模型输出 Schema 校验；
- 评测记录和版本回滚。

### 4.2 大模型职责

大模型只处理需要语义判断的模块：

1. **GoalSpec Builder**：通过有限追问把目标转成能力规格。
2. **Claim Selector**：判断哪些核验证据值得当前用户学习。
3. **Pack Planner**：按学习目标、前置知识和认知顺序组织卡片。
4. **Card Writer**：在给定证据内生成中文解释、例子和迁移任务。
5. **Assessment Writer**：生成与目标对应且答案唯一的题目。
6. **Visual Planner**：决定是否需要图，以及适合的图形语法。
7. **Evaluator**：按固定量表评价候选内容，但不能替代程序门禁。

模型不能决定证据是否真实，不能直接改写快照，不能绕过候选审核发布内容。

### 4.3 Provider 接口

文本和图片模型不得直接散落在业务代码中。统一接口建议如下：

```python
class TextModelProvider:
    def generate_json(self, task, schema, inputs, idempotency_key): ...

class ImageModelProvider:
    def generate(self, visual_spec, idempotency_key): ...

class ContentEvaluator:
    def evaluate(self, artifact, rubric, evidence): ...
```

每次调用保存：Provider、模型版本、提示词版本、输入哈希、输出、耗时、费用、重试次数和错误类型。

## 5. 分阶段实施

## M1：证据约束的高质量中文卡片

### 目标

消除当前自动卡片的通用模板感，同时保证任何事实都没有超出核验证据。

### 开发任务

- 新增 `TextModelProvider` 和本地 Fake Provider。
- 定义版本化的 `CardDraft` JSON Schema。
- 输入包含 GoalSpec、用户水平、相关主张、证据原文和信源信息。
- 输出包含标题、导语、解释段、例子、边界、关键点和迁移任务。
- 生成后执行引用覆盖、数字一致性、禁用表达和正文密度检查。
- 失败时最多修复一次；仍不合格则保留失败原因，不创建候选包。
- 缓存相同证据、目标和提示词版本的结果。

### 验收门槛

- 所有事实性段落都关联至少一条 EvidenceClaim。
- 引用中的数字与证据完全一致。
- 正文覆盖唯一明确的学习目标。
- 不使用“值得注意”“在当今时代”等通用填充句。
- Golden Set 人工评分平均不低于 4/5。
- 同一输入重复运行不重复收费、不生成重复版本。

## M2：目标诊断与动态学习路径

### 目标

让用户自建目标从表单记录升级为可执行、可验证、可调整的学习计划。

### 开发任务

- 新增 GoalSpec Builder，最多提出三个高信息量问题。
- 为目标生成前置知识、能力证据和 3–7 个里程碑。
- 对模糊目标给出可编辑草案，用户确认后才成为 active。
- 根据复习结果更新 concept mastery，不直接修改历史卡片。
- Planner 每次只生成下一个最小学习包，不一次性生成整条路径全部正文。
- 保留七条推荐路径作为模板，不把它们作为硬编码课程。

### 验收门槛

- 每个 active 目标都有可观察的成功证据。
- 每张卡能映射到一个里程碑和一个能力缺口。
- 用户修改目标后旧学习记录保留。
- 系统可以解释“为什么下一步推荐这张卡”。

## M3：语义配图与视觉质量门禁

### 目标

每张图承担明确的理解任务，图形形式随概念变化。

### 开发任务

- Visual Planner 先选择 `none`、流程、对比、时间线、层级、矩阵、坐标、因果链、架构或场景插图。
- 确定性图使用 SVG/HTML 渲染；场景插图再调用 Image Provider。
- 每张图保存要解释的命题、图形类型、alt、图注和读图结论。
- 增加 OCR 检查、文本溢出检查、重复布局检查和证据一致性检查。
- “每卡至少两张图”改为可实验配置；没有理解价值时允许不生成。

### 验收门槛

- 每张图都能回答一个明确问题。
- 同一学习包内不连续使用完全相同的图形语法。
- 图中文字无截断，移动端可读。
- 删除图片后若理解测试不下降，该图应被质量门禁拒绝。

## M4：题目质量与延迟复习闭环

### 目标

使用真实回忆表现，而不是阅读完成状态，决定后续学习。

### 开发任务

- 每道题保存其覆盖的 learning objective 和 evidence claim。
- 增加答案唯一性、选项歧义和答案泄露检查。
- 完成“到期复习 → 作答 → 反馈 → mastery 更新”的前端流程。
- 记录正确性、置信度、耗时、错误类型和是否查看提示。
- 使用 mastery 和遗忘风险调整今日安排。

### 验收门槛

- 100% 题目映射到学习目标。
- Golden Set 中不存在两个合理正确选项。
- 复习结果能改变下一次间隔或后续卡片难度。
- 用户能查看错误原因，而不只看到正确答案。

## M5：资讯发现与微知生产闭环

### 目标

将现有 AI 资讯 workflow 接入微知，但只把与用户目标相关的高价值事件转成学习内容。

### 开发任务

- 接入资讯 workflow 的标准事件与证据格式。
- 增加 canonical event、跨源去重、来源优先级和冲突展示。
- 为快变内容保存有效期和重新核验时间。
- 先计算“与当前目标的能力相关性”，再进入 Pack Planner。
- 没有高价值事件时允许当天不生产资讯包。

### 验收门槛

- 同一事件多来源不重复生成卡片。
- 时点事实显示发布日期和核验时间。
- 二手内容能够回溯到一手来源。
- 无关热点不会占用用户的每日学习预算。

## M6：真实实验与生产化

### 目标

证明新方案能够提高学习效果，再将 v2 设为默认版本。

### 开发任务

- 完成三篇 Golden Set 文章的固定回归。
- 进行“一篇一卡”与“一目标一卡”的 A/B 对比。
- 完成至少 7 天真实学习实验。
- 增加浏览器端回归、任务恢复、备份恢复和模型降级测试。
- 增加认证、运行监控、错误告警、数据备份和部署文档。
- 达标后将 `ui_version` 默认值切换为 v2，并保留 v1 回滚开关。

### 验收门槛

- 24 小时和 7 日回忆率优于当前基线。
- 用户完成率没有因正文变长而明显下降。
- 抓取、模型或图片服务失败不会破坏已有数据。
- 生产部署可以从备份完整恢复。

## 6. 测试方案

### 6.1 固定测试用例

| 编号 | 输入 | 主要验证点 | 期望结果 |
|---|---|---|---|
| T1 | Hugging Face Text generation 教程 | 英文技术材料、条件限定、多个相关命题 | 生成 2–3 张中文卡；保留 decoding 条件；信源可点击 |
| T2 | Agent Harness Golden Set PDF | 长文拆解、概念关系、教学顺序 | 按 Context、Loop、Tools、Memory 等目标拆卡，不按章节机械切分 |
| T3 | 含大量参数表和代码的网页 | 清洗稳定性 | 代码和表格残片不成为事实主张 |
| T4 | 只有一条发布事实的短新闻 | 价值门禁 | 不单独成卡，记录“证据不足” |
| T5 | 两个来源对同一版本信息表述冲突 | 冲突处理 | 同时展示冲突，不由模型静默合并 |
| T6 | 含百分比、日期和模型版本的文章 | 数字核验 | 生成内容中的数字全部可在证据中定位 |
| T7 | Transformer 数学材料 | 公式解释与视觉选择 | 选择张量/矩阵图，不生成通用流程图 |
| T8 | GitHub 代码仓库 | 源码学习 | 解析入口、调用链、关键状态与运行证据 |
| T9 | 同一请求连续运行两次 | 幂等与成本 | 返回同一候选或缓存结果，不重复调用模型 |
| T10 | 模型超时或返回非法 JSON | 降级与恢复 | 记录错误，可重试，不写入半成品版本 |

### 6.2 自动化测试层级

1. **单元测试**：Schema、门禁、数字核验、主题聚类、调度和状态转换。
2. **契约测试**：文本与图片 Provider 的请求、响应、超时、重试和缓存。
3. **集成测试**：真实快照经过处理后生成候选包，全程使用 Fake Provider。
4. **Golden Set 评测**：固定材料比较内容评分、事实覆盖和同质化。
5. **浏览器回归**：目标创建、添加材料、候选审核、学习、复习和信源跳转。
6. **人工学习实验**：24 小时和 7 日延迟回忆、完成率、主观负荷与迁移任务。

### 6.3 核心指标

| 维度 | 指标 |
|---|---|
| 事实质量 | 支持主张比例、数字一致率、不可追溯陈述数 |
| 教学质量 | 目标覆盖率、解释完整度、前置知识匹配度、模板重复率 |
| 题目质量 | 目标覆盖率、歧义率、答案泄露率、区分度 |
| 视觉质量 | 有效图比例、图形多样性、OCR 错误率、移动端可读率 |
| 学习效果 | 完成率、24 小时回忆率、7 日回忆率、迁移成功率 |
| 稳定性 | 抓取成功率、模型成功率、重试恢复率、重复生成率 |
| 成本 | 每个发布学习包的文本、图片和总调用成本 |

## 7. 发布门禁

候选学习包只有同时满足以下条件才能发布：

- 学习目标明确且可验证；
- 包含一至三张卡，每张预计 5–10 分钟；
- 所有事实性内容均有核验证据；
- 数字、版本和时间信息一致；
- 正文、题目和配图共同覆盖同一目标；
- 题目答案唯一且没有明显泄露；
- 移动端没有正文或图片截断；
- 自动评测达标；
- 人工审核通过，或该类内容已经通过足够规模的真实实验获得自动发布资格。

## 8. 实施顺序与提交策略

建议按照下列顺序开发，每个阶段使用独立提交或 Pull Request：

1. `M1-provider-and-card-writer`
2. `M1-card-quality-gates`
3. `M2-goal-spec-builder`
4. `M2-adaptive-pack-planner`
5. `M3-visual-planner`
6. `M3-image-provider-and-visual-qa`
7. `M4-review-ui-and-mastery`
8. `M5-news-workflow-adapter`
9. `M6-golden-set-and-browser-e2e`
10. `M6-production-rollout`

每个提交必须包含：行为变化、必要测试、迁移说明和回滚方式。不得在同一个提交中同时重写生成逻辑、修改数据库结构和切换默认 UI。

## 9. 原方案中只在修补表面的部分

- 单纯增加正文字数，没有证明用户能记住更多。
- 强制每卡两张图，没有先判断图片承担什么理解任务。
- 增加更多提示词形容词，没有建立证据约束和输出评测。
- 每条路径一次性生成更多卡，没有使用回忆结果决定下一步。
- 增加信源数量，没有先判断内容是否服务于当前能力目标。
- 仅依靠模型自评质量，没有固定 Golden Set 和程序门禁。

## 10. 新路径成立的前提

- 用户愿意明确目标、当前水平和实际使用场景。
- 系统能够保存稳定的原文快照与证据定位。
- 大模型只在受控输入、Schema 和证据边界内工作。
- 所有生成产物都有版本、评测记录和回滚入口。
- 团队愿意使用真实延迟回忆数据调整产品规则。
- 在实验完成前，候选内容继续保留人工发布门槛。

## 11. 验证它的第一步

第一步只实施 M1，不同时改动其余模块：

1. 选取 Hugging Face 教程和两篇 Golden Set 文章；
2. 为同一证据分别生成当前规则版与证据约束模型版；
3. 盲评事实准确、解释深度、同质化、迁移价值和阅读负荷；
4. 24 小时后测试回忆；
5. 只有模型版在事实质量不下降的前提下显著提高教学评分，才继续进入 M2 和 M3。
