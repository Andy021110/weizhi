## 2. 各检查点做了什么

### CP9 目标诊断（M2）

把「我想学 Agent」变成可执行规格：先探（信息够不够、最多 3 个问题）再写规格。

关键约束都做成了硬门禁而不是提示词请求：追问超过 3 个直接拦；
判定「信息不足」却没给问题、或判定「足够」却还在问，都会被拦；
`capability` 写「了解/熟悉」这类无法验证的表述被拒；
`success_evidence` 含「感觉/大概」被拒，且必须带可观察动作。

目标**版本化**：改目标是插新版本而不是 UPDATE，旧版本与其学习记录原样保留
（方案 M2 验收门槛「用户修改目标后旧学习记录保留」）。

### CP10 动态学习路径（M2）

这一层刻意全部确定性、不交给模型——掌握度每天决定用户看到什么，
必须可复算、可解释、可回归测试。

掌握度不是答对率：答错扣得比答对加得狠；**自信地答错额外多扣**
（那说明建立了错误的信心，比不确定而答错更该回炉）；用了提示的答对
掌握度照算但间隔减半。遗忘风险按指数衰减，掌握越牢衰减越慢。
`due()` 按风险降序而非到期时间升序——同一天到期时快忘光的先练。

规划器按**依赖顺序**找第一个未达标里程碑，不直接挑最弱的
（不会画循环图就谈不上定位故障）。`plan_next` 必须返回人话理由，
这是方案 M2「系统可以解释为什么下一步推荐这张卡」的落点。

### CP11 语义配图（M3）

先选图形语法、再决定画什么。9 种语法：flow / compare / timeline / hierarchy /
matrix / coordinate / causal / architecture 由程序渲染 SVG，scene 走图片服务。

模型只做语义判断，**渲染与布局全部由程序完成**。每张图要写清 proposition
（要解释的具体命题）与 reading（读图结论）。门禁查连续同构与文字溢出。

`coordinate` 图**必须给真实数值点**才渲染——从字符串节点编一条折线
等于凭空造趋势数据，而方案 2.1 把「数字改写」列为模型风险。

`MIN_FIGURES` 默认 0：「每卡至少两张图」是方案 2.2 明确列为未验证的假设，
做成可实验配置而不是产品规则。

### CP12 题目质量与复习闭环（M4）

门禁全部是确定性字符串/结构分析，不靠模型自评：选项重复、选项包含
（两个都说得通 → 坏题）、语面套路（以上都对/都不对）、选项长度参差
（正确答案被写长会成为破题线索）、题干泄露答案、目标覆盖率不足 100%。

判卷由程序做，不让模型参与——判卷要是也能错，掌握度整条链路都不可信。
反馈含**错误原因**（方案 M4 要求「用户能查看错误原因，而不只看到正确答案」）
与错误类型粗分类。被门禁拒掉的卡不进入复习，不占复习时间。

### CP13 资讯适配（M5）

`canonical_key` 用「清洗后标题 + 主实体」而不是 URL——URL 天然每条都不同，
拿它做键等于没有去重。跨源合并保留全部来源（冲突要并列展示的前提），
来源按权威度排序。冲突检测比对跨源的可比较事实集合，**如实并列、不静默合并**。

时效按类型分档，`stable` 类不设失效期（原理不会因时间失真）。
生产门禁允许返回 `skip_day`：方案 M5 明确「没有高价值事件时允许当天不生产」，
资讯系统最常见的失败模式是为了不断更硬产，那会直接吃掉学习预算。

### CP14 端到端集成

真实材料走完整链路：目标诊断 → 证据入库 → 规划 → 写卡 → 配图 → 出题
→ 作答 → 掌握度更新 → 今日安排 → 资讯去重与冲突。缺 key 时整体 skip。

## 4. 集成跑出来的一个真问题（已记录未根治）

`plan_next` 会偶发返回 `no_material`：里程碑名是模型生成的自由文本，
而相关性匹配是关键词级的（字符 n-gram 重合）。同一个能力缺口，模型写成
「说出循环的四个阶段」能命中材料，写成「理解循环的本质」就可能命中 0 条，
整份材料被判为不相关。

典型症状是「单独跑通过、全量跑失败」。已写进 `planner.relevance` 的注释，
并列出三级缓解方案：提示词锚定动作 → 扩大匹配字段 → M6 后如仍不稳再考虑
embedding（最后一条要引入依赖，不能为一个匹配问题丢掉「标准库 + 3 个三方包」的约束）。

这不是可以悄悄放过的问题：如果它在生产里发生，用户会看到「今天没有学习内容」，
而他并不知道是匹配没命中。
