# 产品范围决策：保留 / 降级 / 合并 / 删除

> 文档状态：**范围基线**，2026-09-11 由产品负责人确定
>
> 判断标准（唯一）：**如果一个功能不能提高「目标匹配、理解、延迟回忆、迁移使用」
> 中的至少一项，就不应该占据产品主流程。**
>
> 效力：本文件约束后续所有开发。与 `微知v2后续开发方案.md` 冲突时以本文件为准
> （方案是执行基线，本文件是范围基线）。末尾附**代码现状对照表**。

## 1. 必须保留（15 项，构成最小闭环）

用户自建学习目标 · 当前水平与使用场景 · 每日时间预算 · 里程碑 · 信源资料库 ·
原始快照与证据定位 · 学习包 · 一目标一卡 · 候选审核 · 信源跳转 · 即时练习 ·
延迟复习 · 学习状态 · 版本记录与回滚 · AI 资讯发现

```
学习目标 → 可信材料 → 核验证据 → 候选学习包 → 学习卡片
   → 即时练习 → 延迟回忆 → 调整下一步 → （回到）候选学习包
```

## 2. 保留但降低存在感

| 功能 | 从 | 到 |
|---|---|---|
| 七条预设路径 | 固定课程 | **目标模板**：选中后仍按用户水平重新生成 GoalSpec，不给所有人同样三张卡 |
| 用户自建卡片 | 一级入口 | **二级入口**：定位为「记录自己的经验 / 修改 AI 卡 / 加私有材料」，不再要求用户手填标题正文三道题复习题配图 |
| AI 资讯雷达 | 核心学习流程 | **发现层**：100 条 → 去重核验 → 按目标筛 5 条 → 判断学习价值 → 可能只出 1 个学习包 |
| 学习进度页 | 展示生成量 | 只展示决策所需：今天学了多久 / 哪些已掌握 / 哪些将遗忘 / 哪个目标在推进 / 下一步为什么推荐它。抓取数、调用数、生成数移到开发者诊断页 |

## 3. 合并

| 合并项 | 说明 |
|---|---|
| 六种固定卡片类型 | 词汇/精读/数学/通识/技能/代码**从用户界面删除**。它们不是六种学习目标，只是表现形式。系统按目标自动组合内容块：概念解释 / 公式推导 / 代码追踪 / 案例分析 / 对比判断 / 操作练习 |
| 学习计划 + 学习路径 | 合并成一个**学习目标**。用户不需要理解「计划」与「路径」的产品差异 |
| 随堂题 + 复习题 | 合并为**目标验证题库**，按出现时间分层：学完立即 / 24 小时后 / 7 天后。不再维护两套固定数量 |
| 质量巡检 + 坏卡修复 | 合并为一个**候选质量状态机**：生成 → 程序门禁 → 模型评测 → 人工审核 → 发布。**不允许自愈 Agent 静默修改已发布的卡片** |

## 4. 删除的产品规则

| 要删的规则 | 改成 |
|---|---|
| 一篇文章 = 一张卡 | 先抽命题，再按目标组合。可能一篇文章出三张卡、三篇文章出一张卡、或一篇文章无卡可出 |
| 每卡必须 800–1000 字 | 保留 5–10 分钟时间约束，字数由目标难度决定。软范围：简单概念 600–900；技术机制 900–1500；数学/代码正文可更短但要公式、图与练习 |
| 每卡必须两张图（硬规则） | 每张图必须承担明确理解任务；没有必要时可以没有图，复杂概念也可以三张。**验证阶段可暂时保留「两张图」作为实验组配置**，与按需配图对比学习效果 |
| 每卡三道随堂题 + 三道复习题 | 题目数量由目标决定：单一判断目标可能只需一道好题；含概念、边界、迁移的卡可能三道。题必须标注覆盖哪个目标 |
| 每天必须生成新内容 | 当天无值得学的新内容时，只安排复习、练习或继续已有学习包 |
| 八个信源每天自动生成大量卡片 | 信源数量只影响发现范围，不决定卡片数量。生产量服从学习时间预算与内容价值 |
| 所有坏卡自动修复并重新发布 | 允许自动生成修订候选，但重新发布前必须过门禁。**已学过的卡尤其不能静默变化** |
| ReAct Agent 控制所有流水线步骤 | 抓取、去重、快照、核验、调度、发布由**确定性程序**控制。只有六件事交给大模型：理解目标 / 选择高价值命题 / 编排教学顺序 / 生成解释和题目 / 规划配图 / 处理规则判断不了的材料 |
| 复杂通知系统 | 只保留三类：**到期复习、需要用户审核、系统任务失败且无法自动恢复**。荐读提醒、断签焦虑、每日生成报告、普通成功通知取消或默认关闭 |
| 连续打卡作为核心指标 | 可以显示学习天数，但**不用它判断学习质量**。核心指标是：延迟回忆率、目标完成度、实际迁移任务、有效学习时间 |

## 5. 暂时不做

多用户社交 · 排行榜 · 分享卡片社区 · 课程市场 · 复杂勋章积分 · 多套主题皮肤 ·
全自动发布 · 同时接入很多模型 · 原生手机 App · 企业权限系统 · 大而全的数据仪表盘

先完成单用户学习闭环。

## 6. 精简后的信息架构

**四个一级页面**：今天（学什么/复习什么/剩多少时间）· 目标（创建/里程碑/掌握情况）·
资料库（添加材料/看证据/生成候选包）· 进展（延迟回忆/能力变化/下一步建议）

学习包与卡片作为页面内流程打开，不新增一级导航。

**八个核心实体**：`Goal` `Milestone` `Source` `EvidenceClaim` `LearningPack`
`Card` `Assessment` `Mastery`

`CardSpec`、`CardVersion`、处理记录、模型调用记录保留在技术数据层，不暴露给用户。

> 真正要砍的是：**固定格式、固定数量、自动堆积内容、不产生学习反馈**的功能。
> 用户目标、可信证据、学习包、卡片、练习、延迟复习、掌握状态必须保留——
> 它们正是微知区别于普通 AI 摘要工具的地方。

### 7.5 发现层（CP25，已完成）

`recommendations`（Top 3 荐读）不再推送后，只写进 `user_state.daily_picks`
而没有出口——「不推送」是对的，但只写库不给入口等于能力消失了。

现在有 `/api/discover` + 首页「发现」入口，放两样东西：

| 块 | 内容 | 说明 |
|---|---|---|
| `picks` | Agent 挑的 Top 3 荐读（`from: "agent"`） | Agent 被要求「没有好卡就不给」，经常为空 |
| `picks` | 为空时退化成今日新卡（`from: "today"`） | 如实列出，不是硬凑推荐；前端换标题文案 |
| `lab` | 最近的 v2 影子卡（含配图数、题量） | v2 还没进推送，这是它唯一的入口 |

顺带修掉一个**让影子链路事实上停摆**的缺陷：影子任务每天只取 RSS 最新一篇，
而 RSS 置顶几天不变，第二天起必然撞 v1 的「重复卡」门禁——表现是每天都失败，
但失败原因看着像内容问题。实际情况是全库只有 1 张 v2 卡，评审无从看起。
`v2_shadow.fetch_materials` 现在会跳过已出过卡的材料。

### 7.6 荐读链路（CP26，已完成）

上线后发现 `picks` 一直走兜底分支（`from: "today"`）——说明 Agent 从来没
成功挑出过荐读，而这件事**没有任何信号**（过滤静默、日志也不打印）。
三件事叠在一起：

| # | 问题 | 改法 |
|---|---|---|
| 1 | 提示词自我弱化：写着「recommendations 不再推送，只作为 App 内的发现层数据」 | 说清它的地位——发现页全靠它把「今天有一堆卡」变成「这三张先读」 |
| 2 | 要求 source_url **逐字符**匹配，而模型抄 URL 常少协议/多 www | 归一化后匹配（去协议/www/尾斜杠）；**落库仍用候选原值**（卡片按原值建索引） |
| 3 | 过滤完全静默 | 丢弃时打印原因；执行完打印「荐读 N 条」，为空时打印候选数量 |

同时修了一个**从未生效的隔离判据**：`_meta` 原被列在 `save_card` 的
`fixed` 集合里，落库时整块丢弃——`is_shadow_card` 查 `_meta.shadow` 与
`_bridge.shadow` 两处做纵深防御，而前者从来没进过库；`_row_to_card`
重建 `_meta` 也会把 shadow / origin 抹掉。现有影子卡能挡住，只是因为
`_bridge` 那条恰好有值。

`daily_picks` 改为无条件覆盖（含空数组）：只写非空的话，今天没挑出来时
会继续展示昨天那份，而用户看不出它是过期的。

实测：真跑一次管家得到「荐读 3 条」，发现层标题由「今天的新卡」（兜底）
变为「为你挑的」（Agent 挑的）。
